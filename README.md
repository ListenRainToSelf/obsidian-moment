# 此刻 MOMENT · Obsidian 朋友圈式日记插件

> 把日记写成像发「朋友圈」一样自然：碎片、即时、带着氛围感。

「此刻 MOMENT」是一款 Obsidian 第三方插件，把写日记从一个「写作任务」改写为「发一条动态」。单条记录不必成文——一个词、一张图、一句牢骚都是合法内容；界面是仿朋友圈的双视图（信息流 + 下拉全览），读起来轻松，回看起来也充满成就感。

**数据永远在本地的原则**：所有记录都落成标准 markdown 与普通图片附件，任何编辑器都能打开、修改、删除。插件只是「读写它们」，不是「占有它们」。

## 项目结构

```
obsidian-moment/
├── manifest.json          # 插件元信息 / id / minAppVersion
├── package.json           # 依赖与构建脚本
├── tsconfig.json          # TypeScript 配置
├── esbuild.config.mjs     # esbuild 打包配置
├── scripts/
│   └── deploy.mjs         # 构建产物同步进 Obsidian 测试库（npm run deploy）
├── src/
│   ├── main.ts            # Plugin 入口，注册视图与命令，轮询心跳
│   ├── settings.ts        # 设置面板：可配置根目录/命名规则/签名/名言
│   ├── view.ts            # ItemView：封面 + 活跃度 + 信息流 + 下拉全览
│   ├── overview.ts        # 下拉全览：按天/周/月/年聚合
│   ├── cover.ts           # 背景(附件 img.jpg)自动加载
│   ├── dayFile.ts         # 日期文件读写 / frontmatter / 追加
│   ├── activityGrid.ts    # 活跃度格点统计与渲染
├── styles.css             # 界面样式与动效
├── gen-test-data.ps1      # 批量生成历史日程测试数据脚本
└── main.js / manifest.json # 构建产物（复制进 vault 插件目录即可用）
```

### 测试数据生成

需要大量历史日程数据做性能 / 渲染测试时，在 PowerShell 中执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
& .\gen-test-data.ps1
```

脚本默认向 `E:\Documents\obs测试\插件测试\此刻` 生成 `2025-01-01 ~ 2026-09-11` 共 619 个日程文件（每天 1~5 条动态，含随机心情 / 名言，2026 年每月 10 日附一张配图），路径与配图规则可按需修改脚本顶部的 `$base`。

生成的文件与插件写入端格式**完全一致**（保证能被正确解析）：

```md
---
mood: ["平静"]
quote: 慢慢来，反而比较快。
updated: 2026-09-10T12:00:00.000Z
---

#此刻

## 07:08
读了几页书，有一句话在脑子里转了一整天。
![2026-9-10-08-30-15.jpg](../附件/2026-9/2026-9-10-08-30-15.jpg)
> 心情：平静
```

> 注意：PowerShell 5.1 读取含中文的脚本需为 UTF-8 BOM 编码；脚本内 `$times = @($times | Sort-Object)` 的 `@(...)` 不可省略，否则单元素数组会被管道降级为字符串标量，导致时间标题被截断为单字符（如 `## 10:42` → `## 1`），插件将无法识别该条动态。

## 项目使用技术

- **语言**：TypeScript
- **构建**：esbuild（官方 Build a plugin 起手式）
- **平台 API**：Obsidian Plugin API（`Plugin` / `ItemView` / `Vault` / `MetadataCache` / `Workspace`）
- **数据格式**：属主 markdown（YAML frontmatter + `## 时间` 标题块）+ 普通图片附件
- **存储**：纯本地（Vault 文件系统），无需任何云端

## 完整功能

| 模块 | 说明 |
| ---- | ---- |
| 背景 + 签名 | 附件目录放入 `img.jpg` 即自动加载为新背景；签名为一句短文案，居背景右下角 |
| 快速发布（右上角 `＋`）| 输入文字、选心情、可配图；`Enter` 发送、`Shift+Enter` 换行；配图按时间命名落入附件夹 |
| 活跃度格点 | 每格代表一天，颜色随条数渐进加深，构成封面的情绪刻度 |
| 朋友圈信息流 | 倒序消息，每条仅「发布时间 + 心情」两处强制标记，内容自然流淌；分批懒加载 + 自动卸载，首屏只渲染最近一批，滚动到底部附近再自动拉取更早的一批 |
| 信息流懒加载 | 先枚举库内真实存在的「日文件」，按日期倒序排成队列，单批消费 `FEED_BATCH = 30` 个（跳过无正文的空天），滚动到距底部约 400px 时自动追加下一批；刷新时保留已加载深度、不缩回首屏，异步批次带代号保护 + 重绘占位，避免并发插入造成错序或重复 |
| 信息流自动卸载 | 每个「天」为一个分组容器，仅渲染视口上下窗口（上 `1400px` / 下 `2000px`）内的分组；窗口外分组清空内容并以高度占位，配合高度缓存瞬时挂载，长列表不堆 DOM、滚动位置不跳动 |
| 无抽动刷新 | 信息流内容未变时（心跳 / 库事件）逐项比对日期 + 内容签名，跳过整段重建；确需重建时还原滚动位置。移除了逐条入场动画，消除滚动时的抽动 |
| 下拉全览 | 页面顶端下拉带阻尼，越过阈值进入相册式聚合视图；按天/周/月/年四档切换，再次下拉返回 |
| 心情统计 | 鼠标悬停封面时，底部渐变模糊层从下上滑，显示最近 30 天各心情次数与占比（进度条） |
| 背景高度段 | 共 7 档，可设置封面包裹背景图片显示第几段（顶→底）；鼠标悬停封面时整图展开 |
| 心情候选 | 设置面板可自由添加 / 删除发动态时可选的心情 |
| 每日名言 | 灰分界线 + 名言，区分活跃度与信息流（随机 / 自定义） |
| 轮询 + 事件监听 | 订阅 vault 改动即时通知；30s 心跳与窗口重获可见 / 焦点时强制读磁盘，兜底库外新增或直接写入的文件 |
| 设置面板 | 可配置根目录（绝对/相对路径）、命名规则、签名、名言池 |

## 安装使用方法

### 1. 构建插件

本仓库为源码工程。请在根目录执行：

```bash
npm install        # 安装依赖（拉取失败时使用镜像源：npm config set registry https://registry.npmmirror.com）
npm run build      # 构建，产物为 main.js
```

### 2. 安装到 Obsidian

构建完成后，将 `main.js`、`manifest.json`、`styles.css` 三个文件复制到 Obsidian 的插件目录：

```
您的库路径/.obsidian/plugins/obsidian-moment/
```

然后在 Obsidian「设置 → 第三方插件」中启用「此刻 MOMENT」。

### 3. 使用

- 在左侧栏点击「此刻」图标（或执行命令「此刻 MOMENT：打开朋友圈」）打开视图。
- 首次使用请在「设置 → 此刻 MOMENT」中配置根目录（库内相对路径），如 `日记`。
- 向 `附件` 目录放入 `img.jpg` 即可更换朋友圈背景。
- 点击顶部背景右上角的圆形「＋」快速发布一条动态。

> 完整的人工验收清单见 [TEST.md](TEST.md)（发布→读回、背景、下拉全览、聚合、外部改动同步等）。

### 数据文件规范（默认）

```
# 根目录
├── 附件
│   ├── img.jpg                  # 朋友圈背景（固定名）
│   └── 2026-9
│       └── 2026-9-10-18:58:30.jpg   # 按时间命名的附件
└── 2026-9
    └── 2026-9-10.md             # 按天命名的正文（mood/quote 在 frontmatter）
```

### v0.2.8
- 新增：信息流**自动卸载（DOM 窗口化）**。每个「天」为一个分组容器（`.moment-feed-group`），只有落在视口上下窗口（上方保留 `FEED_RETAIN_ABOVE = 1400px`、下方保留 `FEED_RETAIN_BELOW = 2000px`）内的分组才真正渲染；窗口外的分组会清空内容并以 `height` 占位（`.moment-feed-group--void`），滚动回看时按高度缓存瞬时挂载 —— 长列表不再无限堆积 DOM，避免资源不足
- 新增：分组高度缓存（`feedHeights` + 内容签名 `feedSig`）。卸载时记录测得高度，重新挂载时先按缓存高度占位再渲染，配合 `display: flow-root` 隔离外边距，滚动位置不跳动
- 优化：窗口计算用 `requestAnimationFrame` 节流（`scheduleFeedWindow`），并在 `resize` 时重算；`applyFeedWindow` 采用「先只读采集位置、再统一挂载 / 卸载」两遍处理，避免读写交错触发反复回流
- 修复：滚动 / 静置时**严重抽动**。根因有两个：① 每条 `.moment-post` 的入场动画 `moment-rise` 在每次追加时都会重播；② 心跳（30s）/ 库事件刷新会把整段信息流 `empty()` 后重建，图片全部重新加载。现已移除该入场动画，并让 `renderFeed` 在内容未变时**跳过重建**（逐项比对日期 + 内容签名），仅在真正变化时才重建且重建后还原滚动位置

### v0.2.7
- 修复：信息流「长日常」翻到深处后日期错乱（旧日期跑到新日期上方，观感像重新加载了最新内容）。旧实现是「从今天起按天盲扫」，且与刷新 / 心跳触发的重绘并发插入；现改为**先枚举库内真实存在的日文件（`listDayDates()`），按日期倒序排成队列**，再按 `FEED_BATCH = 30` 逐批消费，批次严格倒序追加，配合渲染代号（`feedGen`）与「重绘占位」（`feedLoading`）杜绝并发污染
- 修复：信息流永远翻不到底。旧实现以固定上限 `FEED_MAX_DAYS = 3650`（约 10 年）为终点，远超过真实数据量，导致在数据结束后的空天上无限空转；现以「真实日文件队列消费完毕」为终点，翻完即提示「没有更早的动态了」并停止继续请求
- 优化：首屏填充（`fillViewport`）与滚动触底（`maybeLoadMoreFeed`）统一走同一真实队列，不再空扫不存在的日期
